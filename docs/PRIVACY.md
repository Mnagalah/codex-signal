# Privacy and local data

Signal connects to the current desktop's local, version-bound IPC stream. The stream can contain transcript payloads. Signal immediately reduces snapshots/patches to the metadata and lifecycle fields it needs, discards bodies, and does not persist or log the transcript. It is inaccurate to say it never receives text payloads.

Retained fields include original chat/host IDs, project association and icon, titles, stage, timing, local slot history, and local acknowledgements. Mac settings/state stay under `~/Library/Application Support/CodexMenuStatus/`. Linux settings use `$XDG_CONFIG_HOME/codex-signal/` (default `~/.config/codex-signal/`); IDs/slots/acknowledgements use `$XDG_STATE_HOME/codex-signal/` (default `~/.local/state/codex-signal/`). Its transient same-user UI socket is `$XDG_RUNTIME_DIR/codex-signal/ui.sock`, inside a private directory with a mode-0600 socket; it is not a network port. The backend owns business state; GNOME receives only the metadata projection and fixed UI actions. This directory is user data, never a release asset. The desktop's explicit locale setting is read to choose Chinese or English; unrelated configuration values are not exported.

No analytics, advertising, external status service, API key or extra inference call is used by this plugin. Following/unfollowing applies only to Signal's observer. It never approves commands, resumes tasks, sends messages or writes Codex read receipts. A user click opens the original Codex chat; Codex may then apply its own normal read behavior. Signal's local checkmark only acknowledges its own reminder.

Payload reload uses the existing in-process queue to transfer recently observed host/chat identities, minimal project-association fields and any pending explicit unread intent. It never transfers transcript bodies or treats an old turn snapshot as fresh state. This handoff is not a persistent history inventory. Adapter health reports protocol incompatibility separately from an empty chat list.

Private `recovery.json` additionally retains visible identity hints and up to 128 recently observed inactive host/chat IDs, last-observed time, and only `workspaceKind`/`cwd`/`projectId` context. It has no titles, turns, task phase, request bodies or owner identity. The hints let a new process query already-observed chats without scanning account history. Desktop presence replay can discover chats already followed before Signal starts, for local and remote hosts. Missing replies are unavailable, not proof of deletion. Do not publish this file.

Archive handling retains a local hidden-ID marker and minimal project-association fields so a late stream cannot revive that chat and unarchive can respect project preferences. A deleted marker retains no title, turn or project context. This does not mark the chat read. Local lifecycle reconciliation opens the same profile's `state_5.sqlite` read-only and selects only `id`/`archived` information for already-known local IDs; it does not enumerate history or query remote IDs against the local database. No Codex database or rollout is written.

Capture diagnostics are off in public `mcp.json`. A developer who deliberately enables `CODEX_MENU_STATUS_CAPTURE=1` can capture Signal's own views and metadata locally; titles and project names in those files are private. Do not attach raw `status.json`, `slots.json`, `recovery.json`, screen captures, socket payloads, config files, account data or session exports to public issues. Use fictional fixtures and report only versions, expected behavior and the minimal redacted error.

Open-source uploads are made from a whitelist export, not from the development directory or user data. Private evidence stays outside this repository. The HTML demo uses fictional names. See the maintainer release checklist before publishing any screenshots or artifacts.
